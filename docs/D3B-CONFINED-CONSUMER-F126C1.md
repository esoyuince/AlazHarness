## What the accepted kernel experiment verifies

Wrong profile inode/loop, default minimal/two-store layout and default mountinfo
access are refused. After first runner, the old three-store selector still
refuses its new scaffold; only the explicit mode admits the second startup.
Cold wrong-schema check refuses before writable parent opens or epoch advance.
Native owner opens exactly3connections. Preparing/checking/detaching the consumer
opens no fourth connection, no raw database file and changes no SQL rows.

Attached consumer blocks direct original-owner close. An open transaction in any
of the three stores refuses detach without rollback/cancellation. API -> runner
-> consumer detach preserves caller handles. Changed response application header
after detach blocks original owner closure; deliberate fixture restoration allows
normal close. The caller's profile lease remains until all3handles close. Live
native registered writer blocks lease release. Separate contender cannot acquire
until release, while a still-live confined process continues to block volume
shutdown. Only after process exit does original volume supervisor detach image
and release its lease. Second exec reopens retained rows/inodes at the next epoch.

Final UID/GID/caps/groups/no-new-privs/seccomp and namespace identities are read
from the actual process. Landlock canary read/write denial, hidden private host
paths, inaccessible host TCP/abstract/sibling/ambient sockets, closed inherited
FD and fresh private scratch are checked. Namespace reentry is denied under the
combined dropped-capability/seccomp policy; errno alone is not claimed to identify
which independent kernel defense denied it. Existing mounted roots are unchanged.
