## Scoped decision

Two actual unprivileged Linux scenarios now close and reopen the SAME completed
profile with its original helper files and three database inodes. Normal compute
and declared compute failure each preserve the first result/admission/generation,
replay the old request without another computation, accept one new request at the
new epoch, and close the three original-owner handles normally. A second trusted
retained receipt is captured before its caller releases the lease.

This is two cold owner lifetimes in ONE Python process, not process termination,
power loss, machine reboot, namespace confinement or authenticated HTTP. No real
LLM/tool/memory-manager/provider acceptance. Only AIAgent factory/computation/close
is a bounded fixture; OS/user/file/mount/cold helpers/SQLite/scheduler/worker/result
and owner cleanup are real. Previous L139 fresh profile acceptance is retained.

capture(owner) only after a normally CLOSED NativeStoreStartup, detached finite
consumer and still-held caller lease. It is a trusted caller input, analogous to
PreparedStoreExpectation, NOT a signature or a capability safe against arbitrary
same-process mutation. Persistence/distribution of trusted receipts across process
boundaries is not accepted by this same-process test.

Capture validates the tool-discovery cache against the unchanged native source:
paths come from the already hash-qualified manifest, not cache content. Actual
native AST discovery verdicts and stat data must match every entry. Receipt binds
native feature, profile path/inode, all three DB identities, previous epoch and

that JSON is opened. The receipt is not a deployment migration contract. Native source qualification
remains separate; cache-byte changes need a newly captured trusted receipt.
Relocating the native deployment or persisting receipt trust across processes was
not tested and is not accepted by this scope.

Startup explicitly selects retained_profile=receipt with prepared three-store
layout. The exact additions are empty auth.lock, empty cache/documents, private
runtime directory with empty active_sessions.lock, active_sessions.json containing
ONLY entries:[], and bounded hash-bound tool_discovery_cache.json. Files remain
in place. Config/auth.json/.env/hooks payloads/other cache or runtime files remain
forbidden. No stale/live session pruning, source/header rewriting, DB recreation,
new scheduler/store owner or default cold/prepared allowance. Metadata enforces
private modes, UID/GID/device, regular types, single links and bounded size.
Readers refuse observed change and aliases; hostile same-UID ABA is not claimed.

All old callers with retained_profile=None continue the old cold/default checks.
