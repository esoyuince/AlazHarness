## Required distinctions

The v1 execution ledger binds claims to a profile/principal, NOT a run. A report
must not claim one run's exact cost from those totals, even for a profile that
happens to have one visible admission. A reserved provider attempt proves budget
commit, not network delivery. Settled unknown usage or unresolved claims are not
zero usage and no refund permission follows from absence of a response.

The task outcome must reuse LocalRecoveryInspector semantics. An admission with
outcome completed can have a RESULT completed=false/max_iterations_reached; text
is preserved but taskSucceeded is false. Native aggregate and provider-reported
known usage are separate scopes. Exact invoice/tokenizer claims are excluded.

report contract says prompts, outputs and diagnostics must not be leaked here.
Use known fixed enums, never stringify arbitrary values; malformed input should
not become a free-text display field. No stored profile or product bytes changed.

test_active_arbitrary_admission_outcome_is_not_echoed.
