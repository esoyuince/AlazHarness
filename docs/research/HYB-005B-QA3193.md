## Final scope qualifications for adoption

This slice is a literal-loopback OpenAI-compatible provider relay and native
file registry guard on one trusted profile. It is not an arbitrary HTTPS provider,
per-agent trust isolation, remote tariff verification or whole-Gateway egress
firewall. A configured fixed maximum token exposure is reserved before sending;
reported usage cannot replenish it. The provider must actually obey its declared
ceilings for that exposure to bound a real bill. No tokenizer, invoice or real
pricing contract has been qualified. Treat unknown or newly routed models as
unqualified; do not copy fixture rates into production.

The relay buffers SSE before returning it. Tests of SSE validation do not establish
live token streaming latency or early consumer cancellation semantics. Physical
HTTP failure can consume a reservation without completed inference; this is not
an exactly-once execution promise. Separate host bearer/provider credential and
registered handler provenance are checked, but a malicious same-process plugin
or OS user is outside this boundary. Filesystem path TOCTOU, arbitrary other tools
and independently configured clients remain separate work.

The runner's source-code drift rejects initial live-code experiments. Qualified
native acceptance must use the final product hashes after all fixes. An exit0
